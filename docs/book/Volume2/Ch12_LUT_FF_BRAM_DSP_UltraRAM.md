## 12.1 LUT — 만능 논리 흉내꾼

**LUT**
/lʌt/
러트 (Look-Up Table, 조회표)
**진리표를 작은 메모리에 저장해두고, 입력을 주소로 써서 답을 "찾아보는" 부품.**

### 원리 — 계산하지 않고 찾아본다

1장에서 게이트는 트랜지스터의 조합이었습니다. FPGA는 다른 접근을 씁니다:

> **"어떤 논리 함수든 진리표만 있으면 정의된다. 그럼 진리표를 통째로 저장해두면 되잖아?"**

```
6입력 LUT = 64칸짜리 초소형 메모리 (2⁶ = 64)

 입력 A,B,C,D,E,F (6비트)
        │
        ▼  6비트를 주소로 사용
 ┌────────────────┐
 │ 0번 칸: 0       │
 │ 1번 칸: 1       │   ← 이 64칸의 내용이
 │ 2번 칸: 1       │      비트스트림으로 채워짐
 │  ...            │
 │ 63번 칸: 0      │
 └───────┬────────┘
         ▼
       출력 1비트
```

칸 내용을 바꾸면 같은 부품이 AND도, XOR도, 6입력짜리 임의 함수도 됩니다. **"회로를 다시 짠다" = LUT들의 표 내용과 그들 사이 배선을 바꾼다.** 이것이 FPGA 재구성의 실체입니다.

### 왜 6입력인가

입력이 많을수록 LUT 하나가 큰 논리를 삼키지만 내부 메모리가 지수적으로 커집니다(2ⁿ). 통계적으로 6입력이 면적-활용도 균형점이라는 것이 업계 수렴 결과입니다. 우리 리포트의 "LUT6 25,975개"는 6입력을 꽉 채워 쓴 LUT 수예요.

## 12.2 FF — 박자 기억 소자

**Flip-Flop (FF/Register)** — 3장에서 배운 그 플립플롭. FPGA에는 LUT 옆에 FF가 짝으로 배치되어, **LUT(조합 논리) → FF(저장) → LUT → FF ...** 리듬으로 회로가 구성됩니다.

```
     조합 논리        저장         조합 논리
 ──►[ LUT들 ]──►[ FF ]──►[ LUT들 ]──►[ FF ]──►
                  ▲                    ▲
                 clk                  clk
     한 클럭 안에 통과해야 하는 구간 = LUT 사슬
```

> 이 그림이 **타이밍(13장)의 무대**입니다. 두 FF 사이의 LUT 사슬이 길수록 신호가 오래 걸리고, 클럭 주기를 넘으면 타이밍 위반.

**CLB** /ˌsiːɛlˈbiː/ (Configurable Logic Block) — LUT+FF 여러 개를 묶은 FPGA의 기본 타일. "CLB LUT"라는 리포트 표기가 여기서 나옵니다.

## 12.3 BRAM — 내장 메모리 블록

**BRAM**
/ˈbiːræm/
비램 (Block RAM)
**FPGA 안에 미리 만들어둔 SRAM 덩어리.** UltraScale+ 기준 블록당 36Kb(4.5KB).

### 왜 필요한가

메모리를 LUT+FF로 만들면 자원이 순식간에 동납니다(1KB만 해도 FF 8천 개). 그래서 제조사가 **진짜 SRAM 블록을 미리 박아**둡니다. 칩 전체에 912개.

### 우리 숫자 검증

```
ITCM 8KB + DTCM 32KB = 40KB
BRAM 1개 = 4.5KB  →  40 ÷ 4.5 ≈ 9개
실측: 10개  ✅  (제어용 여분 포함, 사양과 정합)
```

> 이렇게 **리포트 숫자를 사양으로 검산**하는 습관이 "Vivado Report를 읽을 수 있다"의 실제 의미입니다.

## 12.4 DSP48E2 — 미리 구워둔 초고속 곱셈기 ⭐

**DSP48E2**
/ˌdiːɛsˈpiː .../
디에스피 포티에이트 이투
**Xilinx FPGA에 하드코딩된 곱셈-누적 전용 블록.** 27×18비트 곱셈기 + 48비트 누산기 + 전치 가산기.

### DSP의 역사

**DSP** (Digital Signal Processing, 디지털 신호 처리)는 원래 1970~80년대에 음성·통신 신호를 실시간 처리하려고 태어난 분야입니다. 신호 처리의 수학(필터링, FFT)은 본질적으로 **곱하고-더하기(MAC)의 반복**이라, TI 등이 MAC 전용 프로세서(DSP 칩)를 만들었습니다. FPGA 제조사들은 이 수요를 보고 **MAC 회로 자체를 FPGA 안에 하드 블록으로** 박기 시작했고, Xilinx 계보의 현행판이 DSP48E2입니다(48 = 누산기 비트 폭).

### 구조

```
        A(27b)   B(18b)
          │        │
          ▼        ▼
      ┌──────────────┐
      │  곱셈기 27×18  │      ← 1장의 "방법 B" 전용 회로
      └───────┬──────┘
              ▼
      ┌──────────────┐
   ┌─►│  48b 누산기   │──► 출력
   │  └───────┬──────┘
   └──────────┘  (누적 = MAC!)
```

MAC 한 번이 **1클럭**에 끝납니다. LUT로 같은 걸 만들면 LUT 수백 개 + 여러 클럭 + 긴 타이밍 경로.

### DSP Inference — Vivado가 알아서 골라주는 조건

**Inference(추론)**: 합성기가 RTL 코드를 보고 "이건 곱셈이네" 하고 DSP 블록에 자동 매핑하는 것.

```verilog
// 이런 코드는 DSP로 추론되기 쉬움
always @(posedge clk) p <= a * b;      // 곱셈 연산자 + 레지스터

// 이런 코드는 DSP 추론이 어려움
// - 곱셈을 게이트 수준으로 손으로 풀어 쓴 경우
// - 시프트+가산 구조로 우회 기술된 경우
// - 특정 파라미터로 벤더 중립(GENERIC) 구현을 고른 경우
```

> **우리 프로젝트의 "DSP 6개" 가설과 직결**: Chisel이 생성한 Verilog가 곱셈을 `*` 연산자가 아닌 형태(GENERIC 경로의 명시적 논리)로 뱉었다면, Vivado는 곱셈인 줄 모르고 LUT로 짭니다. 이게 8장의 가설 (a)의 회로 수준 메커니즘입니다.

### 발표용 한 문단

> "DSP48E2는 FPGA에 하드코딩된 1클럭 MAC 블록으로, NPU의 행렬 연산이 자연스럽게 매핑될 자리입니다. 그러나 합성 결과 6개만 사용되었는데, 이는 Coral의 GENERIC 구현 경로가 곱셈을 명시적 논리로 전개해 Vivado의 DSP 추론이 일어나지 않았기 때문으로 분석됩니다. LUT 곱셈은 타이밍 경로가 길어 최대 주파수에도 불리하므로, DSP 추론을 유도하는 것이 성능 개선의 핵심 후보입니다."

## 12.5 UltraRAM — 더 큰 창고

**UltraRAM (URAM)** /ˈʌltrəræm/ — UltraScale+ 세대에 추가된 **대용량 SRAM 블록** (블록당 288Kb = BRAM의 8배). 수백 KB급 버퍼가 필요할 때 BRAM 대신 사용. 우리 합성에서는 사용 0 (TCM 40KB는 BRAM으로 충분).

## 12.6 BUFGCE — 클럭 배달부

**BUFGCE** — 클럭 신호를 칩 전역에 **균일한 지연으로** 분배하는 전용 버퍼(Clock Enable 부착형). 클럭은 수만 개 FF에 **동시에** 도착해야 하므로 일반 배선이 아닌 전용 트리를 씁니다. 우리 설계는 3개 사용(코어 클럭 등).

## 요약·퀴즈

- LUT = 진리표 저장으로 임의 논리 흉내(계산 대신 조회). FF = 박자 저장. 둘의 교대가 FPGA 회로의 리듬.
- BRAM = 내장 SRAM(4.5KB/개). 우리 TCM 40KB ≈ 10개 검산 성공.
- DSP48E2 = 1클럭 MAC 하드블록. **추론되느냐**가 관건이고, 우리 프로젝트의 핵심 미스터리가 바로 추론 실패 가설.
- URAM = 대용량판(미사용). BUFGCE = 클럭 전용 배달망.

**Q (교수님). "LUT 곱셈과 DSP 곱셈의 차이를 타이밍 관점에서?"**
A. DSP는 최적화된 전용 경로라 1클럭 MAC이 가능하지만, LUT 곱셈은 부분곱 생성과 가산 트리가 여러 LUT를 사슬로 거치므로 경로 지연이 크고, 그 경로가 임계 경로가 되어 전체 클럭 주파수를 끌어내릴 수 있습니다.

**퀴즈**: ① 6입력 LUT의 내부 메모리 칸 수는? ② BRAM 1개 용량과 TCM 40KB에 필요한 개수는? ③ DSP48E2의 "48"은?
<details><summary>정답</summary>① 64칸 ② 4.5KB, 약 9~10개 ③ 누산기 비트 폭</details>
