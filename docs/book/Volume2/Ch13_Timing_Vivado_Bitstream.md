# Chapter 13. Timing · Vivado · Bitstream — 회로가 파일이 되기까지

## 13.1 Timing — 빛의 속도와 싸우는 학문

### 근본 문제

전기 신호도 **이동에 시간이 걸립니다.** LUT 하나 통과에 수십 ps, 배선 1mm에 또 수십 ps. 12장의 그림을 다시:

```
 [FF] ──► LUT → LUT → LUT → LUT ──► [FF]
  ▲                                  ▲
 clk ────────────────────────────── clk
      ├── 이 구간 통과 시간 = 경로 지연 ──┤
      클럭 주기보다 길면 → 타이밍 위반
```

**Setup Time** /ˈsɛtʌp/ 셋업 타임 — FF가 값을 안전하게 잡으려면 클럭 에지보다 **약간 먼저** 입력이 안정되어야 하는 최소 시간.

**Slack** /slæk/ 슬랙 — `클럭 주기 − (경로 지연 + 셋업)`. **양수 = 통과, 음수 = 위반.**

**Critical Path** /ˈkrɪtɪkəl pɑːθ/ 크리티컬 패스 (임계 경로) — 칩 전체에서 **가장 느린 경로.** 이 경로가 최대 클럭 주파수를 결정합니다. (1장 리플 캐리의 "맨 왼쪽 자리 기다림"이 원형)

### WNS — 리포트에서 볼 숫자

**WNS** (Worst Negative Slack) — 최악 경로의 슬랙. Implementation 후 **WNS ≥ 0이면 타이밍 클로저 성공.** M4에서 우리가 확인할 단 하나의 숫자가 이것입니다.

```
WNS = +0.5ns  → 통과. 0.5ns 여유
WNS = -2.3ns  → 위반. 어떤 경로가 주기보다 2.3ns 김
   대응: ① 클럭↓ (가장 빠름)  ② 전략 변경  ③ 파이프라인 추가
```

## 13.2 Vivado — 설계도에서 회로까지의 공장

**Vivado**
/vɪˈvɑːdoʊ/
비바도
**Xilinx(AMD)의 FPGA 통합 설계 도구.** 라틴어 "vivus(살아있는)"에서. 2012년 구세대 도구(ISE)를 대체.

### 처리 파이프라인

```
RTL (Verilog/SystemVerilog)
   │
   ▼ ① Synthesis (합성)
논리 네트리스트          "코드 → 게이트 그물망. LUT/FF/BRAM/DSP 추론"
   │                     → 자원 판정 (M3에서 완료 ✅)
   ▼ ② Implementation (구현)
배치·배선 결과           "어느 LUT를 쓰고 어떤 배선으로 잇는가"
   │                     → 타이밍 판정 (WNS. M4의 관문)
   ▼ ③ Generate Bitstream
.bit 파일                "설정 데이터로 변환"
```

- **Synthesis**: 12장의 Inference가 여기서 일어남. 자원 리포트 출처.
- **Implementation**: Place(배치) & Route(배선). 물리적 거리가 정해지므로 **여기서야 진짜 지연을 알 수 있음.** 합성 통과 ≠ 구현 통과인 이유.
- **XDC 제약** /ˌɛksdiːˈsiː/ — "클럭은 100MHz다", "이 신호는 이 핀에" 같은 **요구사항 명세 파일.** 타이밍 판정의 기준이 됩니다. Coral 레포에 ZCU102용 XDC가 없어 **직접 작성**해야 한다는 것이 알려진 리스크였죠. (Block Design을 쓰면 클럭 제약은 대부분 자동 생성됩니다.)

## 13.3 Bitstream — 회로의 스냅샷

**Bitstream**
/ˈbɪtstriːm/
비트스트림
**모든 LUT 표 내용 + 모든 배선 스위치 상태 + 모든 블록 설정을 직렬화한 설정 파일.** (.bit)

FPGA에 전원이 들어오면 이 파일이 칩 내부 설정 메모리(SRAM)에 로드되고, 그 순간 화이트보드에 회로가 "그려집니다". **전원이 꺼지면 사라지므로 부팅 때마다 다시 로드** — FSBL이 하는 일 중 하나가 이것(Vol.3).

> 크기 감각: ZU9EG급 비트스트림은 수십 MB. ITRI BOOT.bin이 17.8MB였던 이유가 "비트스트림 포함"이었죠.

## 13.4 현재 프로젝트 연결

- M3 = ①Synthesis까지 완료. **M4 = ②③을 통과해야 함.** 확인할 숫자는 WNS 하나.
- LUT로 짜인 곱셈(12장)은 경로가 길어 **임계 경로가 될 유력 후보.** 위반 시 클럭을 낮추는 게 1순위 대응 — 목표가 "동작"이므로 정당한 선택.
- Block Design(Vol.3)이 PS 클럭을 공급하므로, 클럭 주파수 변경은 PS 설정 창에서 숫자 하나 바꾸면 됩니다.

## 요약·퀴즈

- 타이밍 = FF 사이 경로 지연과 클럭 주기의 싸움. Slack 음수 = 위반. WNS가 종합 성적표.
- Vivado 3단: Synthesis(자원) → Implementation(타이밍) → Bitstream(파일화).
- 비트스트림은 휘발성 → 매 부팅마다 FSBL이 재로드.
