# Chapter 3. Register와 ALU — 도마와 칼

---

## 3.1 Register — 도마 위의 재료

**Register**
/ˈrɛdʒɪstər/
레지스터
**CPU 안에 있는 초고속 임시 저장 칸.** 플립플롭(1비트 저장 회로) 32개를 묶으면 32비트 레지스터 하나.

### 비유

요리사(CPU)는 냉장고(메모리)의 재료를 **일단 도마 위로 가져와서** 씁니다. 도마는 좁지만(레지스터는 몇십 개뿐) 손이 즉시 닿습니다(같은 클럭 안에 접근).

```
냉장고 (DDR 메모리)     : 수 GB,   접근에 수십~수백 클럭
찬장   (캐시/TCM)       : 수십 KB, 접근에 1~수 클럭
도마   (레지스터)        : 수십 개, 접근에 0클럭 (즉시)
```

### 왜 필요한가

메모리는 **너무 느립니다.** 덧셈 한 번 할 때마다 메모리를 왕복하면 CPU는 대부분의 시간을 기다리며 보냅니다. 그래서 "일할 재료는 미리 도마 위에" 원칙이 나왔고, 거의 모든 현대 CPU는 **레지스터끼리만 연산**합니다:

```
1. 메모리 → 레지스터로 가져온다   (Load)
2. 레지스터끼리 연산한다          (Add, Mul, ...)
3. 결과를 메모리로 돌려보낸다     (Store)
```

이 방식을 **Load-Store 구조**라 하며, RISC-V(6장)의 핵심 설계 철학입니다.

### 플립플롭에서 레지스터로

**Flip-Flop** /ˈflɪpflɒp/ 플립플롭 — **클럭 박자에 맞춰 1비트를 기억하는 회로.** 1장의 게이트들을 되먹임(출력을 입력으로 다시 연결)으로 엮으면 "상태 유지" 능력이 생깁니다.

```
        D ───┬──[플립플롭]──── Q
             │       ▲
      (새 값)│       │ clk (박자)
             │   박자가 올 때만
             │   D의 값을 Q에 저장,
             │   그 외엔 이전 값 유지
```

32비트 레지스터 = 플립플롭 32개가 같은 클럭을 공유하는 것.

> **FPGA 연결 예고**: Vivado 리포트의 "Register ~8,930개"가 바로 이 플립플롭 수입니다. Coral 안의 모든 레지스터·파이프라인 단계 저장소의 합계예요.

## 3.2 ALU — 만능 칼

**ALU**
/ˌeɪɛlˈjuː/
에이엘유 (Arithmetic Logic Unit, 산술 논리 장치)
**덧셈·뺄셈·AND·OR·시프트 등 연산을 모두 갖추고, 선택 신호로 하나를 골라 쓰는 조합 회로.**

```
        A (32b)   B (32b)
          │         │
          ▼         ▼
   ┌─────────────────────┐
   │  덧셈기  뺄셈기       │
   │  AND    OR    XOR    │◄── 연산 선택 (Decode가 결정)
   │  Shift  비교          │
   └──────────┬──────────┘
              ▼
          결과 (32b)
```

- 1장의 덧셈기가 이 안에 들어 있습니다. 뺄셈은 "2의 보수를 더하기"로 덧셈기를 재활용합니다.
- Decode 단계가 명령어를 해석해 "이번엔 덧셈" 하고 선택 신호를 보냅니다.

### 데이터패스 한 바퀴

`add x3, x1, x2` (x1과 x2를 더해 x3에 저장)가 실행되는 흐름:

```
레지스터 파일          ALU           레지스터 파일
 x1 ──────────► A ┐
                   ├─ 덧셈 ──► 결과 ──► x3
 x2 ──────────► B ┘
        (전부 한 클럭 안에 완료)
```

## 3.3 현재 프로젝트 연결

- Coral Scalar Unit 안에 **32비트 레지스터 파일과 ALU**가 이 구조 그대로 있습니다. RV32I(7장)의 레지스터는 32개(x0~x31).
- **베어메탈 코드와의 연결**: `Xil_Out32(addr, val)`을 컴파일하면 결국 "레지스터에 값을 넣고 → Store 명령으로 그 주소에 쓰는" 기계어가 됩니다. 우리가 쓰는 모든 C 코드가 이 장의 부품 위에서 돕니다.
- **합성 관점**: ALU의 덧셈기·시프터는 FPGA에서 **LUT**로, 레지스터는 **FF**로 매핑됩니다. 리포트의 LUT ~49,300 / Register ~8,930 숫자의 정체가 이것.

## 3.4 요약·질문·퀴즈

- 레지스터 = 도마(0클럭 임시 저장, 플립플롭 묶음). ALU = 만능 칼(연산 모음 + 선택).
- Load → 연산 → Store 패턴이 Load-Store 구조이며 RISC-V의 철학.

**Q (교수님). "레지스터와 메모리의 본질적 차이는?"**
A. 둘 다 저장 장치지만 레지스터는 CPU 데이터패스 안에 있어 같은 클럭 내 접근이 가능하고, 메모리는 버스를 거쳐야 해 수십~수백 클럭이 걸립니다. 용량과 속도의 트레이드오프에서 양 극단에 있습니다.
