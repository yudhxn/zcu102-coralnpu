# Chapter 4. Memory와 Cache — 저장의 계층학

---

## 4.1 왜 계층이 필요한가

이상적 메모리는 "크고, 빠르고, 싸다"입니다. 현실에는 존재하지 않습니다. 물리 법칙상 **빠르면 작고 비싸고, 크면 느리고 쌉니다.**

해결책: **계층(hierarchy)으로 쌓는다.** 자주 쓰는 것만 빠른 곳에.

```
          빠름·작음·비쌈
        ┌───────────────┐
        │  Register      │  ~1KB 미만,  0클럭
        ├───────────────┤
        │  Cache / TCM   │  ~수십KB,   1~수 클럭
        ├───────────────┤
        │  DDR (DRAM)    │  ~수GB,     수십~수백 클럭
        ├───────────────┤
        │  SD카드/디스크  │  ~수백GB,   수만 클럭 이상
        └───────────────┘
          느림·큼·쌈
```

## 4.2 SRAM과 DRAM

**SRAM** /ˈɛsræm/ 에스램 (Static RAM) — 플립플롭 비슷한 구조(트랜지스터 6개)로 1비트 저장. **빠르지만 비쌈.** 캐시·TCM·FPGA의 BRAM이 이것.

**DRAM** /ˈdiːræm/ 디램 (Dynamic RAM) — **축전기(콘덴서)에 전하를 담아** 1비트 저장(트랜지스터 1개). 싸고 크지만, 전하가 새서 **수 ms마다 재충전(refresh)** 해야 하고 접근이 느림. ZCU102의 DDR4 메모리가 이것.

**DDR** /ˌdiːdiːˈɑːr/ 디디알 (Double Data Rate) — 클럭의 상승·하강 에지 **양쪽에서** 데이터를 전송하는 DRAM 규격. DDR4는 4세대.

> **FSBL이 하는 "DDR 초기화"의 정체**: DRAM은 켜자마자 못 씁니다. 타이밍 파라미터 설정, 보정(training) 절차가 필요해요. 이걸 해주는 게 부팅 단계의 FSBL입니다(Vol.3). 7/14 부팅 실패 사건이 이 근처에서 났었죠.

## 4.3 Cache — 자동 찬장

**Cache**
/kæʃ/
캐시
**최근 쓴 데이터를 자동으로 담아두는 작은 SRAM.** 프랑스어 "cacher(숨기다)"에서 유래.

### 동작 원리

```
CPU: "주소 1000번 내용 줘"
      │
      ▼
  캐시에 있나?
   ├─ 있음 (Hit)  → 1~수 클럭 만에 전달  ✅
   └─ 없음 (Miss) → DDR까지 가서 가져옴 (수백 클럭)
                    가져온 김에 캐시에 복사해둠
```

**지역성(locality)** 이라는 경험 법칙 덕분에 작동합니다: 프로그램은 최근 쓴 데이터와 그 근처를 다시 쓸 확률이 높다. (반복문을 생각하세요.)

### 캐시의 약점 — 예측 불가능성

Hit이면 1클럭, Miss면 수백 클럭. **언제 얼마나 걸릴지 모릅니다.** 평균은 빠르지만 최악이 보장되지 않아요.

## 4.4 TCM — 수동 찬장

**TCM**
/ˌtiːsiːˈɛm/
티씨엠 (Tightly Coupled Memory, 밀결합 메모리)
**코어에 직결되어 항상 같은 클럭 수로 접근되는 SRAM.** 캐시와 달리 자동 채움이 없고, **무엇을 넣을지 프로그래머가 직접 결정**한다.

| | Cache | TCM |
|---|---|---|
| 채우기 | 하드웨어가 자동 | **프로그래머가 직접** |
| 접근 시간 | Hit/Miss에 따라 변동 | **항상 1클럭 (보장)** |
| 적합한 곳 | 범용 컴퓨터 | **실시간·임베디드** |

### 왜 Coral은 캐시 대신 TCM인가

NPU 연산은 **접근 패턴이 미리 알려져** 있습니다(어떤 가중치를 언제 읽을지 컴파일 시점에 결정됨). 자동 예측(캐시)보다 **계획 적재(TCM)** 가 낫고, 시간이 보장되므로 성능 예측도 정확해집니다. 회로도 캐시보다 단순해서 면적 이득까지 있습니다.

## 4.5 메모리 맵 — 주소로 세상을 통일한다

**Memory Map**
/ˈmɛməri mæp/
메모리 맵
**주소 공간의 구역 배정표.** 어떤 주소 범위는 DDR, 어떤 범위는 하드웨어 레지스터.

```
32비트 주소 공간 (예시)
0x00000000 ┬──────────────┐
           │  DDR 메모리    │
0x80000000 ┼──────────────┤
           │  (비어 있음)   │
0xA0000000 ┼──────────────┤
           │  PL 장치 영역  │ ← Coral 레지스터가 여기 배정됨
0xFF000000 ┼──────────────┤
           │  PS 내부 장치  │ (UART, 타이머 …)
           └──────────────┘
```

**MMIO** /ˌɛmɛmaɪˈoʊ/ (Memory-Mapped I/O) — 하드웨어 장치의 제어 레지스터를 **메모리 주소처럼** 읽고 쓰게 하는 방식. `Xil_Out32(주소, 값)`이 가능한 이유입니다. CPU 입장에서 장치 제어는 그냥 Store 명령이에요.

## 4.6 현재 프로젝트 연결

- **ITCM 8KB / DTCM 32KB**: Coral의 TCM. 합성 리포트의 BRAM 10개가 이 실체(Vol.2, Vol.4).
- **M4의 Address Editor**: Coral의 레지스터/TCM을 **PS 주소 공간 어디에 배정할지** 정하는 작업이 곧 메모리 맵 편집입니다. 거기서 정한 주소가 `xparameters.h`로 나와 베어메탈 코드의 `CORAL_BASE`가 됩니다.
- **데이터 흐름**: ARM이 MMIO로 Coral ITCM에 프로그램을 써넣고(찬장 채우기), Coral master 포트가 DDR(냉장고)에서 데이터를 가져갑니다.

## 4.7 요약·질문·퀴즈

- 크고 빠르고 싼 메모리는 없다 → 계층으로 해결. SRAM(빠름/비쌈) vs DRAM(큼/쌈, refresh 필요).
- 캐시 = 자동·평균 빠름·예측 불가. TCM = 수동·항상 1클럭·실시간에 적합. Coral은 TCM 선택.
- MMIO: 장치 레지스터를 주소로 다룬다. 베어메탈 프로그래밍의 물리적 기반.

**Q (교수님). "왜 Coral은 캐시가 아니라 TCM을 쓰는가?"**
A. NPU 워크로드는 메모리 접근 패턴이 정적으로 알려져 있어 자동 예측(캐시)의 이점이 적고, 항상 1클럭이라는 지연 보장이 성능 예측성과 실시간성에 유리하기 때문입니다. 회로 면적도 캐시 관리 로직이 없어 절약됩니다.

**퀴즈**: ① DRAM이 주기적 refresh를 필요로 하는 이유는? ② `Xil_Out32`가 하드웨어를 제어할 수 있는 이유를 한 단어로?
