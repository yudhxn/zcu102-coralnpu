# Chapter 5. ISA

## 5.1 용어

**ISA**
/ˌaɪɛsˈeɪ/
아이에스에이 (Instruction Set Architecture, 명령어 집합 구조)
**"이 CPU는 어떤 명령어를 알아듣는가"를 정의한 규격서.** 하드웨어와 소프트웨어 사이의 계약서.

## 5.2 비유 — 언어

CPU를 사람이라 하면 ISA는 **그 사람이 알아듣는 언어**입니다.

```
x86 CPU   = 영어만 알아듣는 사람   (인텔/AMD PC)
ARM CPU   = 프랑스어만 알아듣는 사람 (스마트폰, ZCU102의 PS)
RISC-V CPU = 에스페란토를 알아듣는 사람 (Coral NPU)
```

같은 뜻("두 수를 더해라")이라도 언어(비트 패턴)가 다르면 못 알아듣습니다. **x86용 프로그램이 ARM에서 안 도는 이유**가 이것이고, 우리가 Coral용 프로그램을 **크로스 컴파일**(x86 PC에서 RISC-V 바이너리 생성)해야 하는 이유이기도 합니다.

## 5.3 계약서가 정하는 것 / 안 정하는 것

| ISA가 정함 (계약) | ISA가 안 정함 (구현 자유) |
|---|---|
| 명령어 종류와 비트 인코딩 | 파이프라인 단수 |
| 레지스터 개수와 이름 | 캐시 유무·크기 |
| 메모리 접근 방식 | 클럭 주파수 |
| 예외 처리 규칙 | 제조 공정 |

> **같은 ISA, 다른 구현**이 가능합니다. RISC-V ISA를 따르는 칩은 수백 종이지만 전부 같은 프로그램을 돌립니다. Coral도 그중 하나의 "구현"이에요.

## 5.4 CISC vs RISC — 역사의 갈림길

**CISC** /sɪsk/ 시스크 (Complex Instruction Set Computer) — 명령어 하나가 복잡한 일을 통째로 하는 설계. 1970년대까지의 주류(x86의 뿌리). 메모리가 극도로 비싸던 시절, 프로그램을 짧게 만들기 위한 선택.

**RISC** /rɪsk/ 리스크 (Reduced Instruction Set Computer) — **단순한 명령만 남기고, 대신 빠르게** 돌리는 설계. 1980년대 버클리·스탠퍼드에서 나온 반란. "복잡한 명령은 어차피 컴파일러가 잘 안 쓴다. 단순 명령을 파이프라인으로 빠르게 돌리는 게 이득이다."

역사의 판정: **RISC 승.** ARM(모바일 전체), 그리고 RISC-V가 그 후예입니다. x86조차 내부적으로는 명령을 RISC풍 마이크로 연산으로 쪼개 실행합니다.

# Chapter 6. RISC-V

## 6.1 용어와 역사

**RISC-V**
/ˌrɪsk ˈfaɪv/
리스크 파이브
**2010년 UC 버클리에서 시작된 개방형(free & open) ISA.** V는 버클리 RISC 계보의 5번째라는 뜻.

### 왜 만들어졌는가

기존 ISA는 전부 **사유물**이었습니다. ARM 명령어로 칩을 만들려면 라이선스비(수억~수십억)를 내야 하고, x86은 아예 라이선스를 안 팝니다. 버클리 연구진은 수업·연구용으로 자유로운 ISA가 필요했고, 아예 **누구나 영원히 무료로** 쓸 수 있게 공개했습니다.

결과: 학계 표준 → 산업 확산. 구글이 Coral NPU의 ISA로 RISC-V를 고른 것도 이 자유 때문입니다. **NPU에 명령어 확장을 마음대로 추가**할 수 있으니까요 (ARM이었다면 계약 위반).

## 6.2 모듈식 설계 — 레고 블록 ISA

RISC-V의 천재적인 부분: **기본(base)은 최소한으로, 나머지는 전부 선택 확장(extension)으로.**

```
RV32I     ← 기본: 32비트 정수. 이것만으로 완전한 CPU (7장)
   + M    ← 곱셈/나눗셈 확장 (8장) ★우리 프로젝트의 핵심 쟁점
   + F    ← 부동소수점(실수) 확장
   + A    ← 원자적 연산 (멀티코어 동기화)
   + C    ← 압축 명령 (코드 크기 절감)
   + V/Zve← 벡터(SIMD) 확장
   + Zb*  ← 비트 조작 확장
   ...
```

임베디드 칩은 필요한 것만 골라 담아 **회로를 작게**, 고성능 칩은 다 담아 **빠르게**. 하나의 ISA가 마이크로컨트롤러부터 슈퍼컴퓨터까지 커버합니다.

## 6.3 Coral의 ISA 문자열 해독 ⭐

README에 있는 이 문자열을 이제 읽을 수 있습니다:

```
rv32imf_zve32x_zicsr_zifencei_zbb
```

| 조각 | 뜻 |
|---|---|
| `rv32` | 32비트 RISC-V |
| `i` | 기본 정수 명령 (필수) |
| **`m`** | **곱셈/나눗셈 확장** ← 8장에서 정면 분석 |
| `f` | 단정밀도 부동소수점 |
| `zve32x` | 임베디드용 벡터 확장 (32비트 요소) — **Vector Unit의 ISA 근거** |
| `zicsr` | 제어·상태 레지스터(CSR) 접근 |
| `zifencei` | 명령 캐시 동기화(fence.i) |
| `zbb` | 기본 비트 조작 |

> **주목**: 문자열에 `m`이 **있습니다.** 즉 ISA 계약상 Coral은 곱셈 명령을 알아듣습니다. 그런데 합성 결과 DSP가 6개뿐이었죠. "계약(ISA)에는 있는데 구현(하드웨어)은 어떻게 되어 있나?" — 이 긴장이 8장과 Vol.5의 분석 주제입니다.

# Chapter 7. RV32I

## 7.1 기본 골격

**RV32I** — RISC-V 32비트 기본 정수 명령 집합. 명령이 **47개뿐**이지만 완전한 컴퓨터가 됩니다.

- 레지스터: **x0 ~ x31, 32개** (각 32비트). 특별한 x0은 **항상 0** (쓰기 무시). "0"이 워낙 자주 필요해 아예 상수로 박아둔 것.
- 모든 명령은 **32비트 고정 길이** → Decode가 단순 → 파이프라인에 유리 (RISC 철학).
- **Load-Store 구조**: 메모리는 lw/sw로만 접근, 연산은 레지스터끼리만 (3장의 원칙 그대로).

## 7.2 명령 몇 개 읽어보기

```asm
add  x3, x1, x2    # x3 = x1 + x2         (레지스터끼리 덧셈)
addi x3, x1, 10    # x3 = x1 + 10         (즉시값 덧셈)
lw   x5, 0(x10)    # x5 = 메모리[x10+0]    (Load Word)
sw   x5, 4(x10)    # 메모리[x10+4] = x5    (Store Word)
beq  x1, x2, LOOP  # x1==x2면 LOOP로 점프  (분기 = PC 변경)
sll  x3, x1, x2    # x3 = x1 << x2        (왼쪽 시프트 = ×2^x2)
```

한 줄씩:
- `add x3, x1, x2` — 레지스터 파일에서 x1, x2를 꺼내(3장) ALU 덧셈기(1장)에 넣고 결과를 x3에 저장.
- `lw x5, 0(x10)` — x10에 담긴 주소로 메모리(4장)에 가서 32비트를 읽어 x5로. Coral에선 이 주소가 DTCM이나 DDR.
- `beq` — 조건이 맞으면 PC(2장)를 LOOP 주소로 강제 변경. if/while의 정체.
- `sll` — **Shift Left Logical.** 1장의 "시프트 = ×2"가 명령어로 존재합니다.

## 7.3 RV32I에 없는 것 ⭐

**곱셈이 없습니다.** `mul`은 RV32I에 없고 **M 확장** 소속입니다.

그럼 RV32I만 있는 칩에서 `a * b`는? — 1장의 답: **Shift + Add 반복을 소프트웨어(명령어 열)로** 수행합니다. 컴파일러가 곱셈을 sll/add/beq 루프로 풀어 씁니다. 수십 클럭짜리 곱셈이 되죠.

> 이 사실이 우리 프로젝트 성능 분석의 열쇠입니다. 8장으로 이어집니다.

## 7.4 현재 프로젝트 연결

- Bazel로 빌드한 `coralnpu_v2_hello_world_add_floats`의 `.elf` 안에는 **이 장의 명령어들**이 들어 있습니다. (`f`가 있으니 부동소수점 add도)
- ARM이 AXI로 ITCM에 써넣는 것 = 이 명령어들의 비트 패턴. Coral Scalar가 그걸 Fetch-Decode-Execute.
- `.vmem` 파일 = 이 비트 패턴을 시뮬레이터 메모리에 초기값으로 넣기 위한 텍스트 표현.

## 요약·질문·퀴즈 (5–7장 통합)

- ISA는 HW/SW 계약. 같은 ISA에 다양한 구현 가능. RISC가 역사의 승자.
- RISC-V는 개방형·모듈식. Coral 문자열 `rv32imf_zve32x_...`을 조각별로 읽을 수 있어야 한다.
- RV32I는 47개 명령의 최소 완전 집합, 곱셈 없음(M 확장 소속). x0는 항상 0.

**Q (교수님). "왜 구글이 Coral에 RISC-V를 썼겠나?"**
A. 개방형이라 라이선스 제약 없이 NPU 특화 확장(벡터, 커스텀 명령)을 추가할 수 있고, 기존 컴파일러·툴체인 생태계를 재사용할 수 있기 때문입니다. 사유 ISA였다면 확장 자체가 계약 위반이거나 고비용입니다.
