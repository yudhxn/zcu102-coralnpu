# Chapter 7. RV32I — 47개 명령으로 만드는 완전한 컴퓨터 (심화판)

---

## 7.1 레지스터 파일 — x0~x31

RV32I는 **32개의 32비트 레지스터**(x0~x31)를 정의합니다. 관례적 별칭(ABI 이름)이 있어, 어셈블리에서는 번호 대신 이 이름을 씁니다.

```
x0  = zero  ← 항상 0. 쓰기 무시. "0이 자주 필요해서 아예 배선으로 고정"
x1  = ra    (return address)   함수 복귀 주소
x2  = sp    (stack pointer)    스택 포인터
x3  = gp    (global pointer)   전역 데이터 포인터
x4  = tp    (thread pointer)
x5~7, x28~31 = t0~t6           temporary (임시, 함수 호출 시 안 지켜짐)
x8  = s0/fp (saved / frame pointer)
x9, x18~27  = s1~s11           saved (함수 호출 시 지켜짐)
x10~17      = a0~a7            argument/return (함수 인자·반환값)
```

### x0가 왜 하드웨어에 필요한가

산술에서 "0"은 압도적으로 자주 등장합니다(초기화, 비교, 마스킹). 레지스터 하나를 **회로 배선으로 영구히 0에 묶어두면**, 그 값을 만들려고 별도 명령을 실행할 필요가 없습니다. 부수 효과로 우아한 트릭도 생깁니다: `add x0, x0, x0`는 실질적으로 **아무 일도 안 하는 NOP 명령**이 됩니다 — 별도의 NOP 인코딩을 새로 정의할 필요가 없어졌습니다.

## 7.2 명령어 6가지 형식

RV32I의 모든 명령은 32비트 고정 길이지만, 담는 정보에 따라 6개 형식으로 나뉩니다.

```
R-type (레지스터-레지스터 연산)
┌────────┬─────┬─────┬──────┬─────┬────────┐
│ funct7 │ rs2 │ rs1 │funct3│  rd │ opcode │   add, sub, and, or, xor, sll...
└────────┴─────┴─────┴──────┴─────┴────────┘

I-type (즉시값 연산, 로드)
┌──────────────┬─────┬──────┬─────┬────────┐
│  imm[11:0]   │ rs1 │funct3│  rd │ opcode │   addi, lw, jalr...
└──────────────┴─────┴──────┴─────┴────────┘

S-type (스토어)
┌────────┬─────┬─────┬──────┬────────┬────────┐
│imm[11:5]│ rs2 │ rs1 │funct3│imm[4:0]│ opcode │   sw, sb, sh
└────────┴─────┴─────┴──────┴────────┴────────┘

B-type (분기)
┌──────────┬─────┬─────┬──────┬─────────┬────────┐
│ imm[12,10:5]│ rs2 │ rs1 │funct3│imm[4:1,11]│opcode│  beq, bne, blt...
└──────────┴─────┴─────┴──────┴─────────┴────────┘

U-type (상위 즉시값)
┌────────────────────────┬─────┬────────┐
│      imm[31:12]        │  rd │ opcode │   lui, auipc
└────────────────────────┴─────┴────────┘

J-type (점프)
┌────────────────────────┬─────┬────────┐
│  imm[20,10:1,11,19:12] │  rd │ opcode │   jal
└────────────────────────┴─────┴────────┘
```

> **패턴을 눈여겨보세요**: `opcode`는 항상 최하위 7비트, `rd`는 항상 같은 위치, `rs1`도 항상 같은 위치. 이렇게 **필드 위치를 최대한 통일**해두면 Decode 회로가 형식을 완전히 판별하기 전에도 일부 필드(rs1 등)를 미리 꺼내 쓸 수 있어 하드웨어가 단순해집니다 — 이것도 RISC 철학의 실천입니다.

## 7.3 명령어 전체 훑기 (47개 요약)

```
산술/논리 (레지스터끼리, R-type)
  add sub and or xor sll srl sra slt sltu

산술/논리 (즉시값, I-type)
  addi andi ori xori slli srli srai slti sltiu

메모리 접근
  lb lh lw lbu lhu    ← Load: byte/halfword/word (부호있음/없음)
  sb sh sw             ← Store

분기 (B-type)
  beq bne blt bge bltu bgeu

점프
  jal jalr

상위 즉시값 (U-type)
  lui auipc

시스템/기타
  ecall ebreak fence
```

### 몇 개를 한 줄씩 분석

```asm
lui   x5, 0x10000     # x5 = 0x10000000 (상위 20비트를 세팅, 하위 12비트는 0)
addi  x5, x5, 0x40    # x5 = x5 + 0x40  → 0x10000040 (32비트 주소를 두 단계로 조립)
```
**왜 두 명령이 필요한가?**: 명령어가 32비트 고정인데, opcode·rd 등이 이미 자리를 차지해 즉시값 필드가 최대 20비트(U-type)나 12비트(I-type)뿐입니다. **32비트 값 하나를 통째로 넣을 자리가 없어서**, 상위 20비트(lui)와 하위 12비트(addi)를 나눠 조립합니다. 이것이 "고정 길이의 대가"입니다(CISC였다면 긴 명령 하나로 가능).

```asm
loop:
  lw    x5, 0(x10)      # x5 = 메모리[x10]
  addi  x5, x5, 1        # x5 = x5 + 1
  sw    x5, 0(x10)      # 메모리[x10] = x5
  addi  x10, x10, 4      # x10 += 4 (다음 워드로 포인터 이동)
  bne   x10, x11, loop  # x10 != x11 이면 loop로 (반복문의 정체)
```
5줄이 정확히 `for`문 하나입니다. `bne`가 PC(2장)를 되돌려 loop로 보내는 것이 반복의 물리적 실체입니다.

## 7.4 RV32I에 없는 것 — 곱셈 ⭐

**곱셈(`mul`)과 나눗셈(`div`)이 RV32I에는 없습니다.** M 확장(8장) 소속입니다.

그럼 M 확장 없는 칩에서 `c = a * b;`는 어떻게 컴파일될까요? 1장의 답을 명령어로 구현하면:

```asm
# c = a * b  (a=x10, b=x11, 결과 c=x12), M확장 없이 소프트웨어로
    li   x12, 0          # c = 0 (누적기 초기화)
    mv   x13, x10        # 작업용 복사본
mul_loop:
    beqz x11, mul_done    # b == 0이면 끝
    andi x14, x11, 1      # b의 최하위 비트 검사
    beqz x14, skip_add
    add  x12, x12, x13    # c += (현재 시프트된 a)
skip_add:
    slli x13, x13, 1      # a를 왼쪽으로 시프트 (×2)
    srli x11, x11, 1      # b를 오른쪽으로 시프트 (다음 비트 검사 준비)
    j    mul_loop
mul_done:
```

**이것이 1장 1.6.2절 "Shift + Add"의 명령어 레벨 실체입니다.** 32비트 곱셈이면 최악 32번 루프 — 곱셈 하나에 수십~백여 클럭이 걸립니다. M 확장이 있으면 이 전체가 `mul x12, x10, x11` **한 줄**로 줄어듭니다(그리고 하드웨어가 몇 클럭에 끝내느냐는 8장에서 별개 문제로 다룹니다).

## 7.5 현재 프로젝트 연결

- Bazel로 빌드한 `coralnpu_v2_hello_world_add_floats`의 `.elf`를 디스어셈블하면(`objdump -d`) 이 장의 명령어들이 그대로 나옵니다.
- 19장 main.c에서 ARM이 AXI로 ITCM에 써넣는 바이트열이 바로 이 명령어들의 비트 인코딩(7.2절)입니다.
- 7.4절의 소프트웨어 곱셈 루프는 **20장의 H2 가설(반복형 곱셈기)** 을 이해하는 데 정확히 필요한 그림입니다 — "명령어 자체가 이렇게 반복되는지" 아니면 "`mul` 명령 하나가 하드웨어 내부에서 이렇게 반복되는지"의 구분이 그 가설의 핵심입니다.
- 7.3절의 `lw`/`sw`가 DTCM 또는(주소에 따라) AXI를 거쳐 DDR까지 갈 수 있다는 점이 4장·15장과 연결됩니다.

## 요약

- RV32I: x0~x31 레지스터(x0는 하드웨어 고정 0), 47개 명령, 6개 인코딩 형식. 고정 길이의 대가로 32비트 상수는 lui+addi로 조립.
- 반복문(`bne`+분기), 곱셈이 없다는 사실, 그리고 그 부재를 소프트웨어 루프로 메우는 방법까지 명령어 수준에서 확인.
