# Chapter 8. M Extension — 곱셈 명령의 정치학

> 이 장은 짧지만, **이 책에서 프로젝트와 가장 직결된 장**이다. 최종 발표에서 "DSP 6개"를 설명하는 논리가 여기서 완성된다.

---

## 8.1 용어

**M Extension**
/ɛm ɪkˈstɛnʃən/
엠 익스텐션 (Multiply/Divide Extension)
**RISC-V에 곱셈·나눗셈 명령을 추가하는 선택 확장.** `mul`, `mulh`, `div`, `rem` 등 8개 명령.

## 8.2 왜 곱셈이 "선택"인가

1장의 통찰을 다시 소환합니다:

> 곱셈은 (A) 작고 느린 Shift+Add 반복으로도, (B) 크고 빠른 전용 회로로도 만들 수 있다.

RISC-V 설계자들은 이 선택을 **칩 설계자에게 넘겼습니다.**

| 칩의 용도 | 선택 | 이유 |
|---|---|---|
| 초소형 마이크로컨트롤러 | M 없음 | 곱셈기 면적이 아까움. 곱셈이 드물면 SW로 충분 |
| 범용 프로세서 | M 포함 | 곱셈이 흔하므로 HW 곱셈기가 이득 |

**ISA에 M이 있다** = `mul` 명령의 비트 패턴을 Decode가 알아듣는다.
**하드웨어 곱셈기가 있다** = Execute 단계에 전용 곱셈 회로가 있다.

이 둘은 **별개**입니다. 여기가 미묘한 지점이에요.

## 8.3 세 가지 시나리오

`c = a * b`를 컴파일·실행할 때 벌어질 수 있는 일:

```
시나리오 1: ISA에 M 없음 (rv32i로 컴파일)
  컴파일러가 mul을 아예 못 씀
  → 곱셈을 sll/add/beq 루프로 전개 (소프트웨어 Shift+Add)
  → 명령어 수십 개, 수십 클럭

시나리오 2: ISA에 M 있음 + 빠른 곱셈기 구현
  mul 명령 1개 → 전용 곱셈 회로가 1~수 클럭에 완료
  → FPGA라면 DSP 블록에 매핑되는 것이 자연스러움

시나리오 3: ISA에 M 있음 + 작은(반복형) 곱셈기 구현
  mul 명령 1개 → 하드웨어가 내부적으로 Shift+Add를 수십 클럭 반복
  → 명령은 하나지만 실행이 느림. 회로는 작음 (LUT 위주)
```

> **핵심 문장**: "ISA 계약은 `mul`을 알아듣는 것만 요구한다. **몇 클럭에 끝내는지는 구현의 자유다.**"

## 8.4 우리 프로젝트의 수수께끼에 적용

관측 사실:

```
① Coral ISA 문자열: rv32imf_... → m 있음 (계약상 mul 지원)
② 합성 리포트: DSP48E2 = 6개 / LUT = ~49,300개
③ NPU인데 곱셈 회로가 거의 안 보임
```

시나리오로 해석하면:

- 시나리오 2라면 Matrix/Scalar의 곱셈들이 **DSP 수십~수백 개**로 잡혔어야 자연스럽습니다.
- 실제는 6개 → **곱셈이 LUT 범용 논리로 합성**되었다는 뜻.
- 가능성 (a): `USE_GENERIC` 파라미터가 벤더 중립 구현을 선택 → Vivado가 DSP 추론을 못/안 함.
- 가능성 (b): 해당 빌드 구성이 곱셈기를 **반복형(시나리오 3)** 또는 축소형으로 생성.
- 가능성 (c): Matrix Unit이 이 빌드 타깃(CoreMiniAxi)에 아예 포함되지 않아, 남은 곱셈이 소량.

> **이 세 가설을 리포트·RTL·실측으로 판별하는 것이 M6 분석이고 Vol.5의 본론입니다.** "왜 DSP가 6개인가"는 버그 리포트가 아니라 **구현 선택의 고고학**이에요.

## 8.5 발표에서 이렇게 설명한다

> "RISC-V에서 곱셈은 M 확장이라는 선택 사항입니다. Coral의 ISA에는 M이 포함되어 있어 곱셈 명령 자체는 지원하지만, **명령 지원과 하드웨어 구현 방식은 별개**입니다. 합성 리포트에서 DSP 사용이 6개에 그치고 LUT 사용이 높은 것은, 곱셈 데이터패스가 FPGA 전용 곱셈 블록이 아닌 범용 논리로 합성되었음을 시사합니다. 저는 그 원인을 세 가지 가설(GENERIC 경로, 반복형 곱셈기, Matrix Unit 미포함)로 나누어 검증했습니다."

이 네 문장이면 1장(Shift+Add) → 5~7장(ISA/RV32I) → 8장(M)이 하나로 꿰어집니다.

## 요약·퀴즈

- M 확장 = 곱셈/나눗셈 명령 8개. 선택인 이유는 면적-속도 트레이드오프를 설계자에게 넘기기 위함.
- "명령을 알아듣는다" ≠ "빨리 실행한다". 구현은 1클럭 곱셈기부터 수십 클럭 반복형까지 자유.
- 프로젝트의 DSP 6개 관측은 세 가설로 설명 가능하며, 판별이 M6 분석의 뼈대.
