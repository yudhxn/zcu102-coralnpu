## 1. 정정 항목

| # | 항목 | ❌ 잘못 설명한 것 | ✅ 실제 |
|---|---|---|---|
| 1 | **대상 NPU** | NVDLA nv_small | **Google Coral NPU** (RISC-V 기반) |

## 2. 특히 중요한 정정 두 가지

### ① FSBL 실패 원인 — 추측이 실물 증거에 졌다

**틀린 설명**
> "Rev 1.1에서 DDR4 SODIMM 부품이 교체되어, 구형 FSBL의 DDR 초기화 파라미터가 새 메모리와 맞지 않는다."

웹 검색 결과를 근거로 **단정**했는데, 이건 일반적인 ZCU102 리비전 이슈였을 뿐 **이 사례의 원인은 아니었습니다.**

**실제 원인** — `.bif` 파일을 직접 열어 확인한 결과:
```
the_ROM_image:
{
  [fsbl_config] a53_x64
  [bootloader]  ...\SD_BOOT.elf
  [destination_device = pl] ...\zcu102_base_trd_wrapper.bit
}
```
→ **`[pmufw_image]` 항목이 아예 없음**
→ 로그의 `PMU-FW is not running` 과 정확히 대응

**교훈**
> 검색으로 얻은 일반론보다 **손에 있는 실물 증거(로그 + 설정 파일)** 가 우선입니다.
> "그럴듯한 원인"과 "확인된 원인"은 다릅니다.

### ② NVDLA 전제가 무너지면 그 위의 설명이 다 무너진다

NVDLA 기준으로 설명한 다음 내용은 **이 프로젝트와 무관**합니다.

- NVDLA 내부 블록 (CDMA, CBUF, CMAC, CACC, SDP, PDP, CDP)
- UMD / KMD 2계층 드라이버 구조
- loadable 파일 형식
- 디바이스 트리에 가속기 등록하기
- nv_small의 64 INT8 MAC 구성

**대신 알아야 할 것** → [`01_coral_npu_구조.md`](01_coral_npu_구조.md)

## 3. 그래도 유효한 것 (NVDLA 단계의 자산)

방향 전환 이후에도 **그대로 쓰이는** 지식입니다. LOG.md에도 같은 취지로 기록돼 있습니다.

| 자산 | 어디에 쓰이나 |
|---|---|
| ZCU102 부팅 절차 (SW6 설정, SD 부팅, UART 콘솔) | M4 |
| 부팅 릴레이 원리 (BootROM → FSBL → PMU → …) | M4 |
| BOOT.bin 구조와 `.bif` 작성법 (bootgen) | M4 |
| `[pmufw_image]` 누락 사건의 교훈 | M4 (재발 방지) |
| 보드가 정상이라는 확증 (2019.1 prebuilt 부팅 성공) | 전 구간 |
| PS/PL 구조, AXI 개념 | M4 |

> **방향 전환으로 버려진 건 "NVDLA 고유 지식"뿐**입니다. 보드·부팅·버스에 관한 것은 전부 남았어요. 오히려 리눅스 스택이 빠져 할 일이 줄었습니다.
