## 1. 정체

- **Google Research / DeepMind 공동 설계**, 2025년 10월 공개된 **오픈소스 NPU**
- **32-bit RISC-V ISA 기반**
- ISA 문자열: `rv32imf_zve32x_zicsr_zifencei_zbb`

**용어 풀이**
- **NPU** = Neural Processing Unit. 신경망 연산 전용 처리 장치
- **ISA** = Instruction Set Architecture. CPU가 알아듣는 명령어 규격
- **RISC-V** = 누구나 무료로 쓸 수 있는 개방형 ISA. 특허료 없이 자기 프로세서를 만들 수 있음

## 2. NVDLA와 결정적으로 다른 점 ⭐

**이 표가 이번 프로젝트 방향 전환의 전부입니다.**

| | NVDLA (이전 대상) | **Coral NPU (현재 대상)** |
|---|---|---|
| 성격 | **고정 기능 가속기** | **프로그래머블 프로세서** |
| 명령어 | 없음 (레지스터 설정으로 구동) | **RISC-V 명령어를 실행** |
| 구동 방식 | 호스트가 레지스터에 값을 씀 | **바이너리(.elf)를 올려 실행** |
| 필요한 것 | 드라이버 (KMD/UMD) | **컴파일된 프로그램** |
| OS | 리눅스 사실상 필수 | **베어메탈 가능** |

### 왜 이게 중요한가

NVDLA는 **"계산기"** 입니다. 스스로 판단하지 않고, 호스트가 레지스터에 값을 하나하나 써넣어야 움직여요. 그래서 그 값을 써주는 **커널 드라이버(KMD)** 가 필요하고, 드라이버는 리눅스를 전제합니다.

Coral NPU는 **"작은 CPU"** 입니다. 프로그램을 메모리에 올려주면 **스스로 명령어를 읽어 실행**합니다.

```
NVDLA:  호스트가 매 순간 지시  →  드라이버 필요  →  리눅스 필요
Coral:  프로그램만 넣어주면 자율 실행  →  베어메탈로 충분
```

> **결론**: 대상 변경이 곧 **리눅스(PetaLinux) 탈출**로 이어졌습니다. 디바이스 트리도, 커널 모듈(.ko)도 필요 없어졌어요. 난이도가 오히려 내려간 방향 전환입니다.

## 3. 3부 구성

```
┌────────────── Coral NPU ──────────────┐
│                                        │
│  Scalar Unit  (RISC-V 코어)            │ ← 제어·분기·일반 연산
│  Vector Unit  (SIMD 128-bit)           │ ← 여러 데이터 동시 처리
│  Matrix Unit  (MAC 배열)               │ ← 행렬곱 = 딥러닝 본체
│                                        │
│  ITCM 8KB / DTCM 32KB (single-cycle)   │ ← 코어 직결 전용 메모리
│  AXI4 manager + subordinate            │ ← 바깥과의 통로
└────────────────────────────────────────┘
```

### 각 유닛의 역할 분담

딥러닝 추론 한 번을 돌린다고 하면:

| 유닛 | 맡는 일 | 비유 |
|---|---|---|
| **Scalar** | "다음에 뭘 할지" 결정, 반복문 제어 | 현장 감독 |
| **Vector** | 활성화 함수 등 데이터 여러 개에 같은 연산 | 단순 반복 작업조 |
| **Matrix** | 행렬 곱셈 (연산량의 대부분) | 주력 생산 라인 |

**세 개가 나뉘어 있는 이유**: 딥러닝은 연산 종류가 섞여 있습니다. 행렬곱만 잘하는 회로로는 제어 흐름을 못 다루고, 범용 CPU만으로는 행렬곱이 느려요. 그래서 **각각 전담**을 둡니다.

## 4. 핵심 개념 셋

### SIMD (128-bit, 256-bit 예정)

**SIMD** = Single Instruction, Multiple Data. **명령 하나로 데이터 여러 개를 동시에** 처리.

```
일반 방식:  더하기 명령 16번  →  16클럭
SIMD 128b:  더하기 명령 1번   →  8비트 데이터 16개 한 번에
```

딥러닝은 "같은 연산을 다른 데이터에 반복"하는 구조라 SIMD와 궁합이 완벽합니다.

### TCM (ITCM 8KB / DTCM 32KB)

**TCM** = Tightly Coupled Memory. 코어에 **딱 붙은 전용 메모리**.

| | 캐시 | **TCM** |
|---|---|---|
| 접근 시간 | 있으면 빠름, 없으면(miss) 느림 | **항상 1클럭** |
| 예측 가능성 | 낮음 | **높음** |
| 관리 | 하드웨어가 자동 | 프로그래머가 직접 |

- **ITCM** (Instruction TCM, 8KB): 실행할 **명령어**를 담음
- **DTCM** (Data TCM, 32KB): 처리할 **데이터**를 담음

> **왜 캐시 대신 TCM인가**: 실시간·임베디드에서는 "평균적으로 빠른 것"보다 **"항상 같은 시간이 걸리는 것"** 이 중요합니다. 캐시 미스로 가끔 느려지면 타이밍 보장이 깨져요.

> **합성 결과와의 연결**: BRAM 10개가 잡힌 것이 대략 8KB + 32KB에 해당합니다. **사양과 실제 합성 결과가 일치**한다는 교차 검증이에요. → `04_합성결과_읽는법.md`

### 파이프라인: 4-stage, in-order dispatch / out-of-order retire

- **파이프라인**: 명령을 여러 단계로 쪼개 공장 컨베이어처럼 겹쳐 처리
- **in-order dispatch**: 명령을 **순서대로** 내보냄
- **out-of-order retire**: 완료(은퇴)는 **순서가 뒤바뀔 수 있음**

> **의미**: 빠른 명령이 앞의 느린 명령을 안 기다리고 먼저 끝날 수 있습니다. 성능은 올라가면서, 발행은 순서대로라 설계가 지나치게 복잡해지지는 않는 절충안이에요.

## 5. AXI4 manager + subordinate — 프로젝트 성립의 열쇠 ⭐

README가 이 항목을 콕 집어 "중요하다"고 쓴 이유가 있습니다.

| 포트 | 방향 | 의미 |
|---|---|---|
| **subordinate**(종속) | 밖 → 안 | **남이 나를 조종**하는 입구. PS의 ARM이 Coral을 설정·시작 |
| **manager**(주도) | 안 → 밖 | **내가 남에게 요청**하는 출구. Coral이 스스로 DDR을 읽고 씀 |

```
ARM(PS) ──[명령]──→ subordinate ─┐
                                  Coral NPU
DDR ←──[데이터 요청]── manager ──┘
```

**둘 다 있어야 하는 이유**: subordinate만 있으면 Coral은 데이터를 스스로 못 가져와서 ARM이 일일이 떠먹여줘야 합니다. manager만 있으면 시작 명령을 받을 방법이 없고요. **양방향이라야** "ARM이 시키면 Coral이 알아서 데이터를 가져다 계산"하는 구조가 성립합니다.

> **용어 참고**: 예전엔 master/slave라고 불렀는데, 현재 AXI 표준은 manager/subordinate로 표기합니다. 문서마다 섞여 있으니 같은 것으로 읽으세요.
